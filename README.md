# Preposition Quest CT — версия с самостоятельной регистрацией преподавателей

Проект работает без сборки: `index.html` лежит в корне и подходит для GitHub Pages.

## Что изменено

- преподаватель может сам зарегистрироваться по имени, email и паролю;
- в кабинете преподавателя есть кнопка «Просмотр курса»: открывается главная страница со всеми 35 карточками, семью Checkpoint и форматами ЦТ без ограничений; отдельный ученический аккаунт не нужен, пробное прохождение не сохраняется в результаты учеников;
- добавлено восстановление пароля преподавателя;
- каждый преподаватель видит только своих учащихся;
- у каждого ученика сохраняется `teacherId` и имя преподавателя;
- сообщения ученика попадают только его преподавателю;
- пользовательские выражения теперь принадлежат конкретному преподавателю и не изменяют базу других педагогов;
- новый ученик получает 8-символьный код доступа;
- обновлены Firestore Rules для разделения данных между преподавателями.
- добавлен постоянный личный банк ошибок: правильные ответы не удаляют ранее допущенные ошибки, включая Checkpoint и тренировочные форматы ЦТ;
- добавлен отдельный выбор авторских тренировочных форматов по образцу РТ 2026/2027: B1–B3 (предлоги), B7–B8 (одно слово к двум устойчивым сочетаниям), B19 (перефразирование с устойчивым выражением).
- расширены банки B7–B8 и B19 до **60 заданий каждый**; на одну тренировку случайно выбираются 20 разных заданий.
- после проверки каждого задания B7–B8 и B19 показываются заполненные предложения и индивидуальная русскоязычная подсказка об устойчивом выражении (120 пояснений в `ct-tips.js`), независимо от правильности ответа.
- там, где контекст допускает несколько естественных предлогов, проверка принимает любой из перечисленных `acceptedAnswers` (например, *look through / over* в карточке `exp_0772`); это работает и в обычной тренировке, и в B1–B3.

Новые режимы используют `ct-formats.js`. Они пока не проверены в живом браузере с Firebase; до публикации нужна педагогическая проверка вариантов ответов и реальное тестирование регистрации и сохранения результатов.

## Важно перед публикацией

В старой версии ученики, коды доступа, сообщения и пользовательские выражения не содержали `teacherId`. Если сразу опубликовать новые правила, старый преподаватель перестанет видеть эти данные.

### Одноразовая миграция старых данных

1. Пока на Firebase опубликованы **старые** Firestore Rules, загрузите на GitHub Pages файл `migration.html` из этого архива.
2. Откройте `.../migration.html` на вашем сайте.
3. Войдите под существующим аккаунтом преподавателя.
4. Нажмите кнопку миграции и дождитесь сообщения `ГОТОВО`.
5. Удалите `migration.html` с сайта.
6. После этого загрузите новую версию сайта и опубликуйте новый `firestore.rules`.

Не запускайте migration.html после того, как на сайте уже зарегистрировались другие преподаватели.

## Настройка Firebase

1. Firebase Console → **Authentication → Sign-in method** → включите **Email/Password**.
2. Firebase Console → **Authentication → Settings → Authorized domains** → убедитесь, что домен GitHub Pages добавлен.
3. Firestore Database → **Rules** → замените правила содержимым нового `firestore.rules` и нажмите **Publish**.
4. После этого преподаватели смогут создавать свои кабинеты самостоятельно на вкладке **Регистрация**.

Ручное создание преподавателя в Firebase Authentication и ручное создание `teachers/{uid}` для новых педагогов больше не требуется.

## Новая структура данных

`teachers/{teacherUid}`
- `displayName`
- `email`
- `createdAt`

`students/{studentUid}`
- `teacherId`
- `teacherName`
- данные прогресса ученика

`studentAccess/{studentUid}`
- `teacherId`
- `studentName`
- `accessCode`

`feedback/{messageId}`
- `teacherId`
- `studentId`
- сообщение и ответ

`customExpressions/{expressionId}`
- `teacherId`
- данные выражения

`flashcardSets/{setId}`
- `teacherId`, `title`, `cards` (пары `front` / `back`), `assignedTo` (UID учеников)
- преподаватель создаёт, редактирует, удаляет и назначает наборы в «Мои наборы»;
- ученики видят только назначенные наборы в «Карточки от преподавателя»;
- импорт: два столбца «английское выражение» и «русский перевод», разделённых **Tab**, одна пара в строке, максимум 200 пар;
- кнопки переворота, перемешивания, смены направления, повторения трудных;
- отметки сохраняются в `students/{studentId}.flashcardProgress`, трудная карточка не исчезает после «Знаю» до нажатия «Убрать из трудных».

**Перед запуском новых наборов обязательно опубликуйте обновлённый `firestore.rules` в Firebase Console → Firestore Database → Rules.** Затем загрузите обновлённые файлы на GitHub Pages. Без новых правил Firestore создание и чтение наборов будут отклонены.

### Оформление и смартфоны (v25)

- Раздел наборов продолжает визуальный стиль основного сайта: тёплый молочный фон, мягкий оливковый, акварельные веточки из `assets/`.
- Обложки наборов, страницы преподавателя и ученика, две стороны переворачиваемой карточки оформлены единообразно.
- Исправлена анимация переворота: класс теперь переключается на существующей карточке, а не при полной перерисовке.
- Для экранов шириной до 620 px добавлены компактные панели, перенос кнопок, крупные зоны нажатия, адаптивная сетка наборов, форма импорта и внутренний скролл таблицы учеников.

### Встраивание Wordwall и Quizlet (v26)

- Преподаватель: кабинет → **Wordwall / Quizlet** → «Добавить упражнение» → название и код `<iframe>` с официального сервиса → выбор учеников.
- Ученик: на карте курса кнопка **Wordwall / Quizlet**; назначенные игры открываются в адаптивном встроенном окне и имеют ссылку для открытия в новой вкладке.
- В Firestore появилась коллекция `externalActivities/{activityId}` с полями `teacherId`, `title`, `provider`, `embedUrl`, `assignedTo`.
- При импорте принимаются **только** безопасные HTTPS-адреса встраивания Wordwall (`wordwall.net/embed/...`) и Quizlet (`quizlet.com/{id}/{mode}/embed`). HTML не сохраняется и не исполняется.
- Wordwall: откройте свою игру → **Встроить → Iframe → Copy**. Quizlet: публичный набор → **Embed / Встроить → Copy HTML**. Обычная ссылка на страницу набора не равна ссылке для встраивания.
- Сторонние сервисы могут устанавливать свои ограничения на доступность упражнения; результаты их игр **не синхронизируются** с прогрессом Preposition Quest CT. При невозможности загрузить окно используйте ссылку «Открыть упражнение в отдельной вкладке».
- Опубликуйте **новые** `firestore.rules` в Firebase, иначе операции с `externalActivities` будут заблокированы.

### Ввод пар вручную (v27)

В редакторе своих карточек клавиша `Tab` внутри поля «Выражение и перевод» вставляет настоящий символ табуляции вместо перехода к следующему полю. `Shift+Tab` по-прежнему переключает фокус. На смартфоне предусмотрена кнопка **«⇥ Разделить выражение и перевод»**, поскольку экранная клавиатура может не иметь Tab. Каждая новая пара начинается с новой строки (`Enter`).

### Предпросмотр преподавателя (v28)

- **Мои наборы → Просмотреть**: преподаватель из собственного аккаунта открывает набор, листает, переворачивает, перемешивает и меняет направление перевода. Кнопки сохранения отметок ученика в этом режиме отсутствуют.
- **Wordwall / Quizlet → Просмотреть**: педагог открывает встроенную игру, как она будет выглядеть для ученика, и возвращается к своей библиотеке.
- Режимы просмотра не требуют входа под учеником и не меняют его прогресс. Доступ к чужим наборам закрыт существующими правилами Firestore.

### Автоматическое предложение заданий к набору (v29)

- Кабинет преподавателя → **Мои наборы → Создать задания**. Генератор предлагает семь режимов: Matching, Quiz (целая фраза в пропуске), Articles, Prepositions, B1–B3, B7–B8, B19.
- **Matching** создаётся сразу из пары «английское выражение — перевод».
- Для предложений генератор использует необязательный **третий столбец** «целое английское предложение с выражением» или точное совпадение с примером из редакционно проверенного основного банка сайта.
- **B7–B8** создаётся, если найдутся два контекста с одним общим словом, или используется подходящее задание из собственного проверенного экзаменационного банка. **B19** предлагается только при совпадении выражения с существующим авторским перефразированием. При отсутствии контекста задания **не выдумываются**.
- Для каждого формата педагог может открыть **«Просмотреть»**, **«Исправить»** (текст и ответ), исключить неудачный пример, добавить собственное задание, затем нажать **«Опубликовать»**. Публикация сохраняется в `flashcardSets/{setId}.activities` и становится доступна назначенным ученикам.
- У ученика на карте курса появляется **«Задания по наборам»** с опубликованными форматами; доступна проверка ответов и повторная попытка. Это отдельный тренажёр, он не изменяет прогресс основных 35 карточек или ЦТ.
- После изменения выражений преподавателю стоит заново проверить и опубликовать ранее созданные задания, потому что они не перезаписываются автоматически.

### Генерация с Cloudflare Workers AI (v30)

- В конструкторе каждого набора рядом с форматами Quiz, Articles, Prepositions, B1–B3, B7–B8 и B19 появилась кнопка **«✦ Создать с ИИ»**. Matching создаётся локально из пар выражений и перевода.
- Frontend отправляет запрос `POST https://prepositions-ct-ai.lukshaolga1982.workers.dev/generate` с Firebase ID token текущего преподавателя в `Authorization: Bearer ...`. Сервер **должен** проверять подлинность токена и профиль преподавателя. Никаких секретных API-ключей в коде сайта нет.
- В запросе передаются до шести выражений и до сорока ранее созданных предложений; сервер должен возвращать `{"status":"draft","tasks":[...]}`. Клиент проверяет структуру, обязательные пропуски и правильные ответы, отбрасывает точные и очень близкие повторения по всему опубликованному банку данного педагога и текущим черновикам.
- Новые задания открываются **в редакторе преподавателя**, а не публикуются автоматически. Учитель может исправить ключи/контекст, отключить задания и затем опубликовать их отдельно.
- Текущий AI Worker ранее настраивался вручную в Cloudflare и не входит в ZIP сайта; перед запуском требуется включённый `workers.dev`, правильный `SITE_ORIGIN=https://lukshaolga1982-ship-it.github.io` и работающий серверный обработчик `/generate` с AI binding `AI`.
- Важно: браузерная проверка действующего Worker с авторизованным Firebase-профилем ещё не проведена; сетевую интеграцию необходимо протестировать на опубликованном сайте. Смысловая уникальность и отсутствие неоднозначных вариантов не могут быть гарантированы алгоритмом, поэтому проверка преподавателем обязательна. Квоты генерации на преподавателя потребуют отдельного серверного механизма перед широким публичным запуском.
