# Preposition Quest CT — версия с самостоятельной регистрацией преподавателей

Проект работает без сборки: `index.html` лежит в корне и подходит для GitHub Pages.

## Что изменено

- преподаватель может сам зарегистрироваться по имени, email и паролю;
- добавлено восстановление пароля преподавателя;
- каждый преподаватель видит только своих учащихся;
- у каждого ученика сохраняется `teacherId` и имя преподавателя;
- сообщения ученика попадают только его преподавателю;
- пользовательские выражения теперь принадлежат конкретному преподавателю и не изменяют базу других педагогов;
- новый ученик получает 8-символьный код доступа;
- обновлены Firestore Rules для разделения данных между преподавателями.
- добавлен постоянный личный банк ошибок: правильные ответы не удаляют ранее допущенные ошибки, включая Checkpoint и тренировочные форматы ЦТ;
- добавлен отдельный выбор авторских тренировочных форматов по образцу РТ 2026/2027: B1–B3 (предлоги), B7–B8 (одно слово к двум устойчивым сочетаниям), B19 (перефразирование с устойчивым выражением).

Новые режимы используют `ct-formats.js`. Они пока не проверены в живом браузере с Firebase; до публикации нужна педагогическая проверка вариантов ответов и реальное тестирование регистрации и сохранения результатов.

## Важно перед публикацией

В старой версии ученики, коды доступа, сообщения и пользовательские выражения не содержали `teacherId`. Если сразу опубликовать новые правила, старый преподаватель перестанет видеть эти данные.

### Одноразовая миграция старых данных

1. Пока на Firebase опубликованы **старые** Firestore Rules, загрузите на GitHub Pages файл `migration.html` из этого архива.
2. Откройте `.../migration.html` на вашем сайте.
3. Войдите под существующим аккаунтом преподавателя.
4. Нажмите кнопку миграции и дождитесь сообщения `ГОТОВО`.
5. Удалите `migration.html` с сайта.
6. После этого загрузите новую версию сайта и опубликуйте новый `firestore.rules`.

Не запускайте migration.html после того, как на сайте уже зарегистрировались другие преподаватели.

## Настройка Firebase

1. Firebase Console → **Authentication → Sign-in method** → включите **Email/Password**.
2. Firebase Console → **Authentication → Settings → Authorized domains** → убедитесь, что домен GitHub Pages добавлен.
3. Firestore Database → **Rules** → замените правила содержимым нового `firestore.rules` и нажмите **Publish**.
4. После этого преподаватели смогут создавать свои кабинеты самостоятельно на вкладке **Регистрация**.

Ручное создание преподавателя в Firebase Authentication и ручное создание `teachers/{uid}` для новых педагогов больше не требуется.

## Новая структура данных

`teachers/{teacherUid}`
- `displayName`
- `email`
- `createdAt`

`students/{studentUid}`
- `teacherId`
- `teacherName`
- данные прогресса ученика

`studentAccess/{studentUid}`
- `teacherId`
- `studentName`
- `accessCode`

`feedback/{messageId}`
- `teacherId`
- `studentId`
- сообщение и ответ

`customExpressions/{expressionId}`
- `teacherId`
- данные выражения

## Что ещё желательно сделать перед рекламой сайта

Для публичного запуска стоит добавить отдельные страницы:

- «О сервисе»;
- «Для преподавателей»;
- краткую инструкцию «Как начать»;
- политику конфиденциальности;
- контакты/обратную связь;
- понятное описание того, какие данные учащихся сохраняются.

Также для полноценного удаления ученика из Firebase Authentication лучше позже добавить серверную функцию Firebase Cloud Functions / Admin SDK. Сейчас кнопка удаления удаляет профиль и прогресс из Firestore, но техническая Auth-запись ученика остаётся в Firebase Authentication.
